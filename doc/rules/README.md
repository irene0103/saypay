# SayPay Core

分帳核心邏輯(spec §5)的純函式實作 + 完整測試。零依賴,可獨立於 UI 驗證。

## 檔案

| 檔案 | 內容 | 對應 spec |
| --- | --- | --- |
| `src/types.js` | 領域型別(Transaction / Settlement / SplitItem) | §4 |
| `src/split.js` | 分帳計算:平均 / 指定金額 / 百分比 + 餘數規則 | §5.1, §5.2 |
| `src/debt.js` | pairwise 債務矩陣 + 結清 + 淨額 | §5.3 |
| `src/*.test.js` | 28 個測試,含 fuzz 與不變式驗證 | §7 |

## 執行

```bash
npm install
npm test
```

## 測試涵蓋

- 火鍋 $600/3 的核心情境(spec §1.4)
- **v0.1 bug**:Amy 付款、三人分帳時,me↔Amy 只算我的份額而非全額(spec §5.3 警告)
- 餘數規則:付款人在名單內 → 歸付款人;純代墊 → 歸 members[0]
- 20 人分帳除不盡
- 結清:全額 / 部分 / 超額反向 / 刪除還原
- 軟刪除與非分帳交易被忽略
- **fuzz(900 個隨機帳本)**:債權總和 === 債務總和、反對稱性、零和

## 效能

5000 筆 × 最多 20 人的全量重算 = **~4.7ms**,遠低於 spec §6.3.1 的 50ms 目標。
證實矩陣非瓶頸,不需預先優化。
